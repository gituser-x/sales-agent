# 后端工程实践

## 异步入库与恢复

入库请求持久化后台任务并发布消息；Worker 处理解析结果，记录状态、进度与错误。消费端使用 prefetch 控制在途消息数量，处理成功后手动 ACK。

失败后转入延迟重试队列，TTL 到期后路由回工作队列；超过次数进入死信队列。Worker 启动时重投数据库内 pending 任务，用于弥补部分发布中断场景。

这是可能重复投递的处理方式，不声明 exactly-once。业务 handler 的状态校验和副作用幂等性需要逐项评估。发布封装设置消息持久化与 mandatory，但未在节选中实现 publisher confirms 或完整 Outbox，不能宣称消息绝不丢失。

入口：[消费 Worker](../code-excerpts/workers/ingest_worker.py)、[队列与发布](../code-excerpts/workers/rabbitmq_service.py)。

## 大文件上传

公开 [流式合并函数](../code-excerpts/uploads/stream_assembly.py) 展示逐块读写和 SHA-256 校验，避免合并阶段把整个文件一次性读入内存。分片校验、上传元数据模型和路径管理属于私有依赖。流式合并不能代表后续所有文件解析阶段均为流式。

## 权限、审计与一致性

原工程通过角色权限和工具权限控制访问，写操作存在单独确认流程。文档发布与向量状态分开管理；重分块后删除旧向量失败时，完整工程提供后台补偿删除任务。

审计记录存在长度限制及可配置隐藏，公开代码不附审计数据。生产权限策略、管理账号与部署配置不随展示版发布。
