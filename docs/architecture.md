# 系统架构与服务边界

系统服务教育销售人员与知识运营人员。用户端面向问答和课程匹配；管理端处理资料入库、审核发布、任务状态与审计。

## 请求链路

前端 → FastAPI 权限依赖 → LangGraph 会话与路由 → RAG / 课程推荐 / 工具执行 → 持久化结果 → 普通响应或 SSE。用户身份从服务端 actor 传入，避免以客户端任意 user_id 作为授权依据。

## 数据职责

| 组件 | 职责 |
| --- | --- |
| MySQL | 文档与分块元数据、会话、业务记录、后台任务、工具审计 |
| Milvus | 稠密与稀疏向量索引、混合检索 |
| MinIO | 上传文件对象 |
| RabbitMQ | 入库与向量化工作分发、延迟重试及死信 |
| Worker | 在请求链路外进行解析及向量任务 |

发布状态与元数据过滤控制知识进入检索的范围。向量异常可尝试数据库关键词回退；重分块后的孤儿向量在完整工程中通过补偿任务处理。

## 设计取舍

- 将上传请求与耗时解析分离，前端通过任务进度感知后台处理。
- 使用显式状态图区分问答与运营操作，避免一个自由生成步骤承担所有职责。
- 工具通过统一执行器记录输入输出和耗时，降低排查跨模块调用的成本。
- 模型、数据库与存储凭证仅留在服务端，不写入公开文档或前端资源。
